## 1. 参考资料的使用边界

用户提供的《通联日频因子说明》整理了四份资料、370 个条目，见 [原文件](C:/Users/lenovo/Downloads/tonglian_official_spec.md)。文首说明部分公式为图像识别结果，可能缺字或有误。

本次参考文件 SHA256：`d0197d3f47acb0855b7f3d5a0276b955d901128b16a3d2e7fc4b0802ce54c676`。仅作来源版本识别，不把文件名称当成定义完整性或正确性的保证。

其中大量“日频”条目，是用分钟、逐笔和报价资料汇总后的每日结果，不能因为最后每天一个数就用日线数据完整还原。当前只用已有日行情筛选容易计算的主题，明确区分：

- 参考改编：参考文件中的含义或类别，自行明确当前日线公式；统一加 `_D` 等项目代码，保留原名称、资料名称和页码，不宣称数值与供应商一致。
- 项目补充：用于展示和检验的基础指标，不声称来自该文件。

当前没有一个条目被标记为供应商完整复现。特别是其按分钟 09:30 收盘定义的收益，可能与当天开盘价不同；截面标准化、20 日处理、方向翻转也不能默认省略后还沿用原名。

## 2. 第一批 10 个公共表达式

所有定义初始为版本 1，所有已登录用户可查看、运行、复制；普通用户不能修改系统版本。收益与偏离都保存为小数。

| 项目代码 / 名称 | 固定表达式 | 最少输入条数 | 来源与差异 |
|---|---|---:|---|
| VWAP_D / 当日成交均价 | `amount / volume` | 1 | 参考改编：日频特征 1–7，VWAP_1D，39 页；明确用日总额/日总股数，源文件公式缺失，覆盖范围一致性须核对 |
| RET_INTRADAY_D / 开盘至收盘收益 | `close_raw / open_raw - 1` | 1 | 参考改编：日频特征 1–7，RET_INTRADAY，33 页；使用日开盘价，不冒充分钟 09:30 收盘起点 |
| RET_OVERNIGHT_D / 昨收至今开收益 | `open_hfq / lag(close_hfq,1) - 1` | 2 | 参考改编：日频特征 1–7，INTRADAY_MOMENTUM_0H，35 页；采用日开盘及同口径调整后昨收，不使用竞价虚拟价格 |
| RANGE_D / 当天高低价幅度 | `high_raw / low_raw - 1` | 1 | 主题参考改编：HF转低频的 AMP_STD，10 页；只是日高低价幅度，不是分钟振幅标准差，也无其截面及20日后处理 |
| VWAP20_D / 20 日成交均价 | `ts_sum(amount,20) / ts_sum(volume,20)` | 20 | 项目补充；窗口含当天，跨除权事件返回原因 |
| VWAP_BIAS_D / 收盘相对成交均价偏离 | `close_raw / (amount / volume) - 1` | 1 | 项目补充；原始价格口径一致 |
| VOLUME_REL20_D / 相对此前20日的量比 | `volume / ts_mean(lag(volume,1),20)` | 21 | 项目补充；不同于资料中的上午/下午量比及09:24:30竞价量比，不沿用 VOLUME_RATIO 名称 |
| MOM20_D / 20 日涨幅 | `close_hfq / lag(close_hfq,20) - 1` | 21 | 项目补充；与 B 的20日收益对照，复用既有计算能力 |
| MA20_BIAS_D / 相对20日均价偏离 | `close_hfq / ts_mean(close_hfq,20) - 1` | 20 | 项目补充；均价窗口含当天，复用 B 的均价能力 |
| VOL20_D / 20 日波动程度 | `ts_std(log(close_hfq / lag(close_hfq,1)),20) * sqrt(252)` | 21 | 项目补充；20个日对数收益的样本标准差换算到年度口径，与 B 对照；不是分钟 RVOL |

表中“输入条数”包含当天。公共因子都在日终后计算，形成下一交易日可使用的信号。

## 3. 暂不选入

| 类别或条目 | 原因 |
|---|---|
| 订单失衡 VOI/OIR、买卖价差、盘口压力 | 需要买卖报价或订单簿 |
| 大单资金流、主动买卖、成交笔数 | 需要逐笔数据、订单编号或成交方向 |
| 上午/下午、开盘后5分钟、最后1小时 | 需要分钟数据，日线不能拆出时间段 |
| 集合竞价各项、竞价收益预测 | 需要虚拟价格、委托量等独立数据；模型还需要训练样本 |
| 分钟相关性、分钟波动、特质收益 | 需要分钟序列、市场基准或额外模型 |
| APB_1D、ARPP_1D、TRAJ_LIQ 的原定义 | 依赖分钟计算，且部分识别公式缺失；不凭名字自行补一个公式后声称复现 |
| 供应商完整标准化后因子 | 尚未明确历史股票池、有效样本、标准差定义及全部处理顺序 |

## 4. 注册时必须保存的信息

每个公共版本保存：项目代码、中文名、完整表达式、语法版本、所需字段、单位、价格口径、历史长度、有效时间、异常规则、维护者、来源文档及页码、原条目名称、改编说明、原文件摘要。

供应商存在同名条目时，来源必须同时含文档名称和原条目名称；不能仅用名称确定定义。暂不推断因子越大是否越好，排序方向由使用者明确选择，不宣称收益有效性。

## 5. 交付验收

- 每个表达式至少一组手算检查和一组真实行情独立计算，零成交、停牌、缺数据、历史不足及除权边界另测。
- MOM20_D、VOL20_D、MA20_BIAS_D 对应的基础量要与 B 已有结果核对。
- 公共与私有走同一引擎；同一表达式和数据复制后数值应一致，权限和运行记录依然按用户隔离。
- 目前的数值可行性检查只支持设计选型，不表示因子库、用户权限或运行服务已经完成。
- 已核对这 10 条表达式的允许字段与函数、历史长度、结构大小和文档引用，见 [本机设计校验记录](../.audit/factor_design_validation.log)。该检查不是产品解析器或完整计算验收。
