# D 交付验收

> 文档状态说明（2026-10-29）：本文保留原阶段的设计、要求或验收语境，不代表所有内容仍待实现或在最新提交已全部重测。当前功能、新增与调整见 [交付与原方案差异](D_当前交付与方案差异.md)，提交前复验见 [分支检查](D_分支交付检查_20261029.md)。

D2 增量的结果另见 [D2_实现验收.md](D2_实现验收.md)。下面是 D 本身的验收记录。

验收日期：2026-10-28。Python 3.12.14，PostgreSQL 16.15。样本为 20 只证券、10,440 条行情。

## 结论

Phase 0 到 Phase 8 的核心功能已在本地实现。10 个公共公式可以查看、复制和计算；私有公式、运行结果和操作记录按登录用户隔离。主要计算在 PostgreSQL 中完成。正式页面用用户名和密码登录，不再手填用户编号。各阶段完整退出条件仍须逐项核对，不能仅据核心功能检查通过判定全部验收完成。

2026-10-29 独立复核发现并修复了额外问题，最终 56 项 C+D 检查通过，并补做真实行情与部分实际浏览器核对；详见 [独立复核记录](D_独立复核_20261029.md)。下文保留原交付时的检查范围与限制，后续进展以复核记录为准。

没有配置外部对话模型，也没有做可选的 Phase 9。没有推送远程。

## 逐项结果

| 项目 | 结果 |
|---|---|
| 表达式 | 规范中的合法公式、拒绝示例、单位、窗口和历史长度有检查。`tests/d` 共 43 项通过 |
| 公共公式 | 10 条已注册。重复安装不增加行；内容冲突会停下 |
| 私有公式 | 另一用户和 AI 工具列不出来，也不能直接读版本 |
| 库内计算 | 2025-06-20 十个公式与独立实现一致。窗口公式的执行计划含 `WindowAgg` |
| 与 B 对照 | 两边都有效时，MOM20、VOL20、MA20 偏离的最大绝对差不超过 0.000001 |
| 原因 | 停牌和零成交会同时保留；跨除权的 20 日成交均价返回 `CORPORATE_ACTION`；缺一天不会用更早数据填上 |
| 未来数据 | 修改研究日之后的成交额，过去运行的输入摘要和结果不变 |
| 登录 | 错误密码和过期会话都会拒绝。普通用户读不到密码摘要 |
| 同一连接 | 异常退出后，下一次事务只看到新的用户和日期 |
| 失败留痕 | 非法公式和失败计算会留下请求记录，不会留下成功的公式或运行 |
| 重复下单 | 同一个提交键只产生一笔订单 |
| 记录保护 | 普通用户、AI 角色和审计角色都不能删除请求记录 |
| 已有库安装 | `zhishi_abc_fixed_sample` 安装后，行情、指标、账户、订单、回测和金额合计不变，并多出 10 个公共公式 |
| 原 C 检查 | 安装 D 之后 9 项仍通过 |
| 恢复 | `zhishi_d_sample` 备份约 1,000,062 字节，恢复到 `zhishi_d_restore_sample` 后内容一致。恢复库通过 13 个 SQL 检查，并用 `demo_user` 算出 19 条 2025-05-30 的结果，`sh.600001` 的当日成交均价为 13.0895 |
| 页面 | 自动检查能登录，并指出 `close_raw>10` 不是合法公式 |
