## 执行规则和总验收标准

依次执行Phase 0至9。每阶段先验证完成标准，再进入下一阶段；常规开发不逐阶段等待用户批准。保留原有未提交内容、`.env`、行情和交易数据；所有破坏性建库或测试只在新建、明确命名的验收副本内执行。

最终必须同时满足：真实模型完成多步工具闭环；两用户隔离与数据库拒绝检查通过；个人提示词可保存和按版本生效；50项公式独立核算通过；统一页面可操作；备份恢复后可继续读取；ABC和原D回归通过。无有效模型密钥时完成全部离线工作，最终明确缺少真实联调证据，不能宣称完整验收。

## Phase 0：保护现状、复核基线和入口

目的：从现有实现增量扩展，避免把旧演示页或测试库当正式结果。

工作：

- 阅读 README_D、交接、验收、统计说明、当前工作记录及本轮D2全部文档。检查 git 状态与本地指令，记录既有未提交内容，不重置。
- 确认 `.env` 实际指向的库，仅记录名称、用途和非敏感连接信息。建立新验收副本；禁止复用或删除原真实行情库。
- 基线运行C/D测试和SQL检查，记录新增测试前的结果。若有既有失败，定位并修复后再继续，不能降低断言。
- 实际打开 `app/ui/main.py` 的8510统一入口，对照8503旧C页。记录页面、启动文件、数据库副本和数据性质。
- 对MA20、VOL20、VWAP20和一个长窗口候选测量查询计划及耗时；先串行测量，再测轻量并发，避免争用时得出错误结论。

产物：`docs/D2_实现验收.md` 的基线部分、独立数据库名称及备份位置（备份不提交）、耗时记录。

通过标准：原数据数量未减少；原功能基线明确；正式入口可见；没有占用用户在用的端口或覆盖正在编辑的内容。

## Phase 1：统一契约和非破坏迁移

建议新增：`app/agent/contracts.py`、`tools.py`、`prompts.py`、`app/setup_ai.py`、`sql/migrations/d2/001_ai_workflow.sql`。

工作：

- 定义不可变 RequestContext、严格工具参数、ToolResult、Evidence、AnswerDraft及错误类别。模型不允许传身份、角色、研究日期或连接信息。
- 统一工具注册表、Schema和调度器；旧 `handle()` 保留兼容。禁止新增说明和旧校验集合不一致。
- 建立提示词、对话、回合、消息、依据及幂等执行记录，字段和约束按设计。owner复合外键、状态枚举、大小限制、不可变版本及索引一并实现。
- 创建所有权策略与最小权限，迁移仅由安装入口运行，事务失败整体回滚。增量安装不重建行情或交易表；新空库安装明确接入重建脚本。
- 更新测试清理顺序，防止新增外键导致旧fixture清理失效。检查事务结束后用户/日期上下文清理。

通过标准：首次与第二次安装均成功，第二次不重复数据；所有者缺失或不匹配时新表拒绝读写；原D检查仍通过。

## Phase 2：DeepSeek 适配器

建议新增：`app/agent/deepseek.py`、独立可验证依赖清单、`.env.example` 的无密钥配置说明。

工作：

- 使用官方Chat Completion协议及可配置模型，默认非thinking、普通非Beta入口。返回 assistant 消息和 tool_calls，保留真实call_id及顺序。
- 只允许服务端受信任配置的目标地址，浏览器用户和模型不能修改base_url。密钥只从服务端环境取，不进入日志、状态或UI。
- 处理401/403、429、5xx、连接中断、超时、空回答、错误JSON及错误参数。网络瞬时错误最多重试2次，计入模型调用次数与总截止时间；权限/格式错误不盲目重试。
- 工具Schema的本地校验独立于API返回；遇到未知工具先拒绝，不执行。
- 未配置时清楚返回MODEL_NOT_CONFIGURED，不自动退回固定回答假装成功。

通过标准：用模拟HTTP响应核对请求地址、鉴权不泄漏、工具来回协议、异常路径和预算；测试不向真实服务发送敏感资料。此阶段的模拟通过不算真实DeepSeek联调通过。

## Phase 3：编译图、循环、预算和持久化

建议新增：`app/agent/workflow.py`、`state.py`、`checkpoint.py`、`service.py`。

工作：

- 使用真正 `StateGraph(...).compile(...)`，节点及条件边按设计；模型读取上次工具结果再决定下一步，不能保留一次plan后固定顺序执行作为新主流程。
- 本轮上下文由认证服务创建；恢复历史只恢复内容，不信任旧token、owner或模型文字。任何访问先确认当前登录与会话归属。
- 默认6次模型请求、12次工具调用、90秒，输入长度/结果大小及取消均有检查；超过上限返回已有结果与限制，不回到循环。
- PostgreSQL保存器的setup只在安装阶段运行。专用运行角色与owner上下文必须贯穿真实保存器读写；验证get/list/put/恢复/删除均受权限限制。不能用普通内存保存器冒充持久化。
- 幂等键绑定用户、thread、turn、操作名、规范化参数及上下文；数据库唯一约束和事务防重。模型call_id只用于协议，不能单独作为防重依据。
- 因子运行和操作成功记录要么同一事务完成，要么使用可验证的幂等映射消除“写成功但响应丢失后重复写”。失败重试只能恢复已知安全操作。

通过标准：模型替身根据真实工具返回选择第二步；达到预算终止；会话重启后保留；并发两用户不串内容；中断后继续不重复产生已成功运行。记录关键节点经过，不能只证明函数被定义。

## Phase 4：个人提示词和答案证据

工作：

- 从 [系统模板](prompts/d2_system.md) 读取维护者提示词；提供 [个人偏好](prompts/d2_user_preferences.md) 默认值与保存服务。普通用户只能维护自己的配置，内容最大4000字符。
- 保存新版本，回合启动锁定版本和system_hash；用户编辑不改变运行中的回合。删除/归档不破坏旧回合引用。
- 将偏好作为低优先级内容；把工具输出与资料名称视作数据，禁止将其拼成高优先级指令。
- 回答引用通过Evidence校验，核对owner、日期、股票池、版本、字段、原值与百分比变换；权威数值直接渲染。
- 无依据数值修复最多一次，仍不合格则仅返回已核验卡片。概念问答允许无工具，但不能出现虚构数据库数值。

通过标准：甲的配置乙不可读；新旧回合版本准确；恶意自定义提示词无法变更权限；null、百分比、不同单位和缺失原因解释测试通过。

## Phase 5：受控工具和数据库防御验收

工作：

- 接入设计列出的13项工具，复用现有因子、统计和历史查询，不复制另一套核心算法。
- `run_factor`只使用上下文中的股票池；`list_my_runs`限定本人和本轮上下文；统计/比较旧运行时必须回显旧上下文，不偷换日期。
- `screen`真正实现受控filters；当前旧工具只传空filter的情况必须处理，不允许向用户声称已过滤。
- 补齐schema类型、长度、数值、日期、排序、股票池大小、可见对象和结果大小检查；限制未来数据和多步查询累积开销。
- 检查受限数据库角色直接访问：跨用户公式、运行、统计、提示词、对话、证据和checkpoint都拒绝；无上下文即拒绝。管理员连接不得用于正常工具。
- 注入/越权场景至少覆盖：用户消息、个人偏好、因子名称、工具结果四种入口；即使模型返回越权调用也不能执行。记录允许/拒绝及原因，不记录秘密。

通过标准：SQL直接访问检查和应用检查都通过；网络或模型异常不会留下越权连接、活动事务或永久“运行中”记录。不得把提示词里的禁止语句当成数据库防御证据。

## Phase 6：扩充50项因子并独立核算

输入：[候选清单](design/d2/public_factors_50.json)、[370项来源索引](design/d2/source_inventory_370.json)。这些是设计数据，不可在应用启动时直接当已验收种子加载。

工作：

- 保留原10项代码、版本、表达式、digest及旧运行；新增40项按代码幂等注册。名称、类别、来源性质、页码、说明、字段、历史长度、单位完整可查。
- 先修正分母零原因归类，分别构造zero volume和zero amount案例；不得按单位含Q就统一标为零成交量。
- 50条均用独立Python实现与数据库逐股票对照，正常数据必须有有效输出。使用至少251交易日、覆盖目标日期的真实行情副本验证长窗口；只在短教学样本看到全部缺失不能算数值通过。
- 验证停牌、交易日缺口、0/负价格、零量零额、缺失、历史不足、除权、未来行情、原价/调整口径及所有统计边界。查询使用完整日期序列，避免先删缺失日导致lag错位。
- 测量各公式耗时。优化现有MA20及长窗口的重复计算、取数范围和查询计划；保持结果不变。目标是在至多100股票/252历史范围内单公式通常5秒内完成，硬上限经实测明确且有界，默认不要无限增大超时。
- 核对370来源索引：122/154/70/24，合计370；保持文档+代码+行号识别，不因重名误去重。对未复现项明确状态，不展示成可运行因子。

通过标准：50唯一代码和表达式；独立逐项对照、缺失原因和统计通过；公共目录重装无重复、私有公式不变；真实与教学样本标签正确。收益可预测性不在本次通过声明里。

## Phase 7：统一界面与可解释过程

建议新增：`app/ui/pages/d_ai.py`、提示词编辑组件、因子分类/搜索组件；修改 `app/ui/main.py` 注册新页。

工作：

- 登录后进入“AI分析”，显示日期、股票池、模型连接状态、对话、新建会话、取消、本人提示词及结果卡片。
- 过程显示“查找公式/检查权限/计算/查询统计/生成说明”的已发生动作和结果，不显示内部推理文本。
- 公式页展示公共50项分类搜索、定义来源、历史长度和复制为私有；提供“问AI解释”带入本人有权查看的版本。
- 保存AI草稿复用现有私有公式流程，不自动发布；任何模拟交易仍在原页面操作。
- 8501至8503旧页面提供统一入口提示；README中仅推荐主入口8510，8511清楚标为验收副本。不能让用户手填编号冒充身份。

通过标准：实际浏览器登录、提问、查看依据、编辑提示词、保存草稿、切换用户、取消、中断恢复、异常提示均操作通过；无模型配置时不出现假回答。截图保存到本地验收目录，用户可见证据避开密码。

## Phase 8：真实模型联调与全面验收

工作：

- 有服务端密钥时使用最小教学样本连接真实DeepSeek，记录模型名、依赖版本、请求时间、耗时及用量，隐藏密钥。仅发送必要的教学资料与聚合结果。
- 至少完成6个真实场景：解释并计算VWAP；两因子统计比较；本人历史运行解释；表达式草稿并检查；信息不足时追问；恶意要求越权时拒绝。
- 对“计算后再解释统计”的场景，证据必须包含模型先选择run_factor，再根据返回run_id选择factor_statistics，最后基于统计回答。不能只录一条自然语言回答。
- 每个真实场景单独检查数据与引用是否正确。真实模型输出不稳定时修契约和流程，不把固定答案接回主界面掩盖问题。
- 运行C+D和新AI完整回归、SQL权限及时间边界检查。若旧断言依赖公共目录数量10，改为核对原10不变与新增40，不能取消归属/数值断言。
- 模拟429、超时、中断、工具错误、数据库取消和重复提交；确认有界退出且不多写。

通过标准：离线与真实结果分别记录；真实场景至少6项逐项通过，安全场景均被程序/数据库保护。缺密钥或服务不可用是明确外部条件，完成能做的部分后如实交接。

## Phase 9：恢复演示与交接

工作：

- 备份专用验收库，恢复到另一个新库，并预建所需角色；备份不包含集群角色，不能漏掉权限准备。
- 恢复后读取50项目录、本人提示词与版本、已有对话、依据和运行；继续新回合，确认旧对象未变且仍隔离。
- 更新README_D、README_D_HANDOFF、D交付验收、D工作记录，增加D2验收与5分钟课堂演示脚本。区分本次新增和既有，不编造完成项。
- 给出启动、安装、离线检查、可选真实联调、备份恢复的真实可运行命令；说明正式入口、库用途、已知限制和验证证据。
- 默认本地交付，不提交秘密或`.audit`，不擅自推送远程。

通过标准：新库恢复后主要流程可跑；主入口清楚；文档链接和命令检查通过；用户无需逐项参与调试。遇到权限/模型配置这类确需用户介入的障碍，再简明说明。

## 实施时的基础检查命令

在项目根目录、已将环境指向专用验收副本后执行。不要把以下检查直接对准需要保留的原库。

```powershell
.\.venv\Scripts\python.exe -m pytest tests/c tests/d -q
.\.venv\Scripts\python.exe scripts/check_d.py
```

`scripts/check_d.py`会安装D且要求数据库名以 `_sample` 结尾。新AI的安装和检查入口由实现阶段新增，并在实际运行后写入交付记录；本计划不虚构尚不存在的验收命令。

370项详细条目成功解析；50项候选全部通过当前表达式语法、单位和复杂度规则，代码与表达式digest均无重复，最大历史251日、最大节点16。证据见 [设计检查记录](design/d2/design_validation.json)。本轮没有执行新增40项的数据库数值对照或真实模型调用；这些是Phase 6和8的工作。
