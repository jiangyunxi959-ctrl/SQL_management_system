## 2. 一条完整的使用流程

用户选择公共或本人私有公式及固定版本 → 选择研究日期区间和历史股票池 → 检查因子与随后收益是否有关 → 看分组表现及缺失 → 创建因子排序策略 → 使用本人费用方案回测 → 同时看毛收益、净收益和成本 → AI解释结果、比较稳健性并给出处。

建议统一页面增加“因子研究”和“因子策略”，费用方案归在本人设置。现有“原策略”继续保留。扩展的重点是连接这些能力，暂不继续堆同类窗口公式。

## 3. 因子评价必须先规定的口径

### 3.1 输入与时间边界

- 固定factor_id、version、syntax/engine版本、表达式digest、历史成员版本、起止日期和评价截止日。公共公式定义共享，评价结果始终属于本人。
- t日收盘后计算当时可知的因子，仅使用不晚于t的信息；默认于下一个交易日开盘形成持仓。不得用t日收盘算出的信号假设以同一收盘价成交。
- 初版评价1/5/20个交易日的后续收益：以t+1开盘为起点，以t+h收盘为终点，h=1代表下一个交易日开盘到收盘。节假日按交易日历计，不按自然日相加。
- 后续收益是评价标签，可在评价截止日内读取，用于检验过去因子；与生成t日信号的查询严格分离。AI不能通过评价工具取到截止日之后的数据，更不能将后续标签送回策略选股。
- 除权分红要使用同口径总回报/调整价或明确的公司行动会计。样本末尾收益尚未到期、停牌、退市、缺价等分别记录，不填零、不擅自顺延到有价格那一天。

### 3.2 先做哪些结果

| 结果 | 定义与展示 |
|---|---|
| 每日IC | 当日截面因子值与后续收益的Pearson相关，按股票代码配对 |
| 每日Rank IC | 因子和收益都按平均秩处理并计算相关，平值不能随意打散 |
| 汇总 | IC均值、样本标准差、正值比例、有效日期和有效股票数；零方差/样本不足为空 |
| ICIR | 均值/样本标准差，未定义时为空；初版不盲目年化或声称统计显著 |
| 分组表现 | 默认5组，历史样本太少时降到3组或不计算，清楚显示每组数量；对照先做等权持有，不冒充可成交策略 |
| 因子方向 | 默认高值优先；反向因子需显式选择并保存，不能看完测试区间结果后自动翻方向 |
| 覆盖与异常 | 每天候选、有效、剔除及原因，避免只展示存活或能成交的股票 |

IC每日至少10个有效配对；不足返回原因。两组变量任一零方差不能把相关记为0。19只教学股票仅适合流程演示，结果标记小样本，不声称发现有效因子。持有期重叠的每日收益并非相互独立，初版不输出错误的显著性检验。

分组收益与实际策略回测分开：前者解释因子排序，后者服从资金、费用、停牌、涨跌停、整数手及买卖约束。长短组收益差可作理论比较，不能在没有融券能力的模拟账户里假装真实可卖空。

## 4. 把公式接入策略

初版支持单因子排序：本人可见的固定公式版本、升/降序、Top N或前百分比、日/周/月调仓、等权目标持仓、初始资金及费用方案。先复用现有撮合与资金账本，再增加多因子组合。

每个信号日记录因子值、候选池、排序、目标持仓和剔除原因；下一交易日执行。无有效信号时默认不新增持仓，已有持仓按预先定义的规则处理；不静默把空结果解释成清仓或换另一公式。费用不足、涨跌停或停牌造成的未成交也要记录。

数据库新增 `research.factor_eval_run/daily/value` 保存评价参数与标签，`research.factor_strategy_version/signal/target` 保存策略版本、当日信号与目标，回测仍关联已有运行、订单、成交和净值。所有版本不可变，归属通过外键、行权限和受限服务保证。计算可缓存，但缓存键必须包含本人可见范围、数据快照和全部时间/公式参数。

## 5. 用户交易成本设置

### 5.1 两种费用模式

1. A股账户模式：本人买卖佣金、最低佣金、是否已含指定费用、印花税和过户费适用规则，以及滑点假设。法定规则按成交日读取；用户优惠只覆盖本人的佣金项目，不能修改全库默认规则。
2. 自定义maker/taker模式：用户设置两种费率及滑点，用于支持这类收费模型的市场或明确标记的教学假设。不是“买入=taker、卖出=maker”，也不是“限价单必为maker”。

maker/taker取决于成交是否立即取走挂单或先提供流动性；同一限价订单也可能部分taker、部分maker。[交易所费用定义](https://help.coinbase.com/en/exchange/trading-and-funding/exchange-fees)

当前只有日线，没有逐笔或盘口，不能可靠判断真实maker/taker。首版默认全部taker，或由用户在回测参数显式选定统一假设，成交记录保存liquidity_assumption；不输出“真实判定maker”的虚假精度。首版两种费率设非负，不模拟返佣；如需返佣，另增有界账本模型。

A股收费包含经纪佣金和适用税费，不直接等同上述模型。规费是否已计入佣金要明确，避免重复计费。[上交所投资者说明](https://one.sse.com.cn/onething/gptz/)

### 5.2 保存与计算

- 新增本人私有 `sim.cost_profile/cost_profile_version`，保存市场、币种、费率小数、最低费用、包含关系、滑点及有效期。页面允许按“万分之几/基点/百分比”输入，但必须明确单位并统一换算；限制NaN、无穷、负值和超界。
- 回测开始锁定费用版本/规则快照。用户后来改费率不能改变旧回测或旧成交。用户甲不能读取或引用乙的私有成本版本。
- 订单冻结资金和执行日资金检查都必须使用同一已锁定成本方案。费用改变后要重新验算买入手数，不能沿用 `unit*1.002` 的硬编码近似；实际手续费只在成交时计提，不对拒单/撤单收费。
- 逐笔记录名义成交额、实际成交价、maker/taker假设、佣金、税费、其他费及滑点估算。金额用精确数值，按既定粒度舍入，汇总从账本读取。
- 新功能让撮合调用一个带cost_version的统一费用入口；旧的 `ref.fn_fee` 作为兼容默认方案。不能先扣旧费用，再额外扣一遍用户费率。
- 对同一份已成交序列，毛利润=净利润+已计入账本的现金手续费（无其他资金流时）；明确标记“同成交口径毛利润”。滑点已经体现在成交价格中，不能再从净值扣一次。估计滑点损失只单独展示。
- 若用户要比较“完全无成本会怎样”，另跑零成本对照账户；成本会影响买得起的数量和后续持仓，不能将其曲线简单视作原曲线加手续费。零成本运行和实费运行分别保存、分别撮合。

展示：实际净利润、同成交毛利润、佣金/税费明细、费用占资金比例、总换手、成交/拒单数量，及毛/净两条曲线。净值是按市价估值的账户利润，仍含未卖出仓位；和“全部卖出后到手利润”分开，不再用“真正利润”掩盖这个区别。

## 6. AI应该如何变得更有用

保留现有受控LangGraph闭环，新增有实际作用的工具：`evaluate_factor`、`evaluation_report`、`compare_evaluations`、`draft_factor_strategy`、`estimate_strategy_cost`、`backtest_report`。每项均有明确的参数、本人归属、截止日、资源上限和证据编号。

用户说“检验20日涨幅对随后5日收益有没有关系，做一个每周持有前三只的策略，佣金换成我的费率”，AI应依次确认日期和样本、运行评价、读覆盖/IC/分组结果、生成策略草稿、列出执行与成本假设。用户在界面确认后才运行会大量写记录的回测，AI再读取结果解释；仍不允许真实下单、任意SQL、修改身份或公共规则。

系统提示词新增：区分因子分布与预测评价、区分评价标签与当时信号、区分理论分组与可成交策略、区分毛/净利润和零成本对照；发现小样本、低覆盖、成本吞噬收益时主动说明，禁止仅挑收益最高的窗口报告。

第一版“财报分析”读取结构化的当时可见财务指标、公告日、可用日、来源和版本变化，展示真实资料链接。不先上任意网页抓取或全文问答；以后支持公告全文时，再加入页码引用、原文与指令隔离、修订记录及外发内容限制。
