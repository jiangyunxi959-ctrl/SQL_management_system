## 1. 范围和通过标准

本轮依据实现方在会话中的修复说明，对照第四次复核的原样例重新运行。通过标准为：

- 升级前没有可靠截止日的完成评价，不能再通过读取、比较或 AI 工具进入当前研究依据。
- 成交量、成交额和股票池成员内容变化后，默认请求重新计算；输入未写入变化时，相同请求继续复用；显式旧编号不能绑定新数据。
- 评价和回测计算期间发生数据变化时，不能发布被错误标记为原版本的结果。
- 本轮改动没有破坏已有检查，原始探测数据恢复。

全量检查使用从上一轮验收副本升级的 `zhishi_d3_fifth_review_20261029_sample`；独立数据修订和中途发布检查使用另一副本 `zhishi_d3_fifth_probe_20261029_sample`，避免相互改变数据版本。正式库、应用代码和密钥未修改，没有推送远程。

当前代码仍标记 ENGINE=d3.4；新的数据版本是持久递增的编号。本轮直接验证实际行为，不用版本标签代替验证。

## 3. 两处旧问题的原样复现

### 3.1 升级前的真实旧评价已被拒绝

直接使用第三次复核生成、第四次仍能越界读取的实际评价 45，而不是新插入一条假旧记录。该评价为 d3.3，真实计算截止日字段仍为空。

在 2025-05-30 的服务端上下文下，report、compare_evaluations、evaluation_report 工具、compare_evaluations 工具均拒绝；提示“没有可靠的计算截止日……请重新计算”。

合法的新评价仍能完成并读取。不能把保护旧数据理解成所有报告都不可读。

### 3.2 原成交量样例现在得到新结果

股票 sh.600001，日期 2025-05-28，公式 amount / volume：

| 状态 | 成交量 | 评价编号 | 公式值 |
|---|---|---|---|
| 修订前 | 141700 | 61 | 13.1192 |
| 修订后默认提交 | 142700 | 62 | 13.02726447091800981079187106 |

第二次确实走了新评价，未强制更换默认请求编号来绕开旧结果。

在成交量修订后再把成交额加 1，评价 64 的值为 13.02727147862648913805185704。随后把同一成员记录的有效期起点改为 5 月 29 日，在成员记录数不变的情况下，5 月 28 日候选少了该股票，变为 18 只。证明成员内容变化也参与计算更新，不再只检查行数。

所有量价和成员内容在 finally 中恢复并查询确认。数据版本继续递增，是恢复写入本身留下的记录，没有把版本倒回去。

## 4. 计算中途变化与数据库防线

独立探测在真实计算完成、即将调用原发布函数之前设置同步屏障；此时提交一笔真实数据修订，再放行原发布逻辑。没有替换公式计算、数据库存取或结果断言。

评价最终 FAILED，因子值 0 行；回测最终 FAILED，净值和成交均为 0 行，原因是“计算期间数据版本已变化，不发布与实际读取不一致的结果”。这是实际执行发布边界的检查，不只是根据函数名推测有效。

代码在计算开始处也加入同一版本核对。本轮没有宣称覆盖所有并发调度、断点恢复和输入冻结场景。

数据库中确认 8 个输入表均安装了版本更新触发器：行情、除权、证券、证券状态、股票池成员、交易日历、费用规则、价格限制规则。普通 app_user 可通过受控函数读取版本，不能直接修改或删除版本表。

## 5. 本机环境异常及重跑方式

首轮全量检查出现密码计算的内存分配错误与数据库连接中断，数据库随后自动恢复。该轮为 91 项通过、2 项失败、12 项错误，**不作为修复已通过的依据**。

恢复后，新的 Python 检查进程又停在 Windows WMI 系统信息查询。通过定时线程栈定位到 platform.machine → Windows 系统信息读取；没有据此修改应用逻辑。

数据库恢复后又退出过一次；确认原服务未运行后，使用原pgdata及原55436端口启动恢复，没有重建或清空数据。第二次单进程检查因连接等待被停止。最终把原有检查分成数据库/公式等81项、原交易6项、页面与统计18项，顺序执行，分别耗时133.86、33.36、33.41秒，全部通过。随后数据库检查顺序执行通过。

最终检查使用本机诊断包装器 `.audit/d3_fifth_review/run_local.py`：仅把不返回的 WMI 元数据查询转为 Python 自带的系统读取后备路径。实际识别仍为 AMD64 / Windows 11；真实密码哈希与校验单独运行通过。权限检查、密码算法、数据库连接、公式计算和测试断言均未替换。包装器没有写入产品代码。

恢复后的探测副本还出现编号与已有记录冲突，仅将该探测副本中落后的编号序列推进到已有最大值；全量检查副本没有需要调整的序列。正式库未改。环境异常及中断日志均保留，最终以完整重跑和独立探测的实际结果为准。

复核前已停止本复核方上轮启动的 8516，没有关闭用户的应用或原有 8510、8512、8513。
