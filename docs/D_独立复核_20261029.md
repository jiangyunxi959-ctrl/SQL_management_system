# D 实现独立复核

日期：2026-10-29。依据本地现有实现、此前设计和实施计划。没有推送、合并或改写远程。

## 结论

核心数据库功能已落地，原有检查可以复现。但原交付不能仅凭“Phase 0—8 完成”一句话视为全部条件已验收。本轮补查发现并修复了脚本入口、重复提交绑定、模型失败记录和公共公式页面入口等问题。

修复后 C+D 合计 **56 项通过**；13 个 SQL 检查及 A 业务、导入、页面检查通过。另在独立的真实行情副本上，对 10 个公共公式共 200 条证券结果与现有独立计算实现核对，通过。

测试均在本轮新建的副本进行：`zhishi_d_review_20261029_sample` 和 `zhishi_d_real_review_20261029_sample`。未重建或清理原演示库、原真实行情库。复制与恢复、测试和浏览器操作会在副本内创建测试用户及业务记录；不是对原库的只读查看。

## 本轮修复

1. `scripts/check_d.py`、`scripts/create_d_user.py`：从文档所说的仓库根目录直接执行时无法导入 app。补上脚本自身的项目根目录定位，不依赖外部 PYTHONPATH。
2. 重复提交原先只按用户和提交键返回对象号，不核对业务类型、公式日期或订单数量；同一个键改参数、甚至跨因子与订单使用都会错误返回旧对象。现在将业务类别与全部输入生成摘要并存入原结果引用字段；相同请求可以重复，变更参数或业务类别明确拒绝。旧记录缺少可验证参数时保守拒绝，不能猜测属于相同请求。
3. 模型 plan 或打开工具会话异常时，原先只留下 START。现在补记 FAILURE，再向上返回真实错误。
4. 公共公式页原先必须先复制私有公式才能在页面运行。增加公共公式直接计算入口，结果仍仅本人可见；复制、保存、版本更新和归档后立即刷新列表。

新增文件：`app/audit/idempotency.py`、`tests/d/test_review_regressions.py`。对现有业务表未做破坏性迁移。结果引用现在保存含对象号及请求摘要的结构，不再只保存裸对象号。

## 实际观察到的限制

- 在同时运行整套检查时，浏览器执行较慢的 20 日均价偏离曾触发 5 秒语句超时；有明确错误，未写入伪成功结果。单独测同一查询约 4.1—4.6 秒，余量偏小。当天成交均价在浏览器成功完成。不能据此承诺良好的多用户并发体验。
- 本轮浏览器核对补上了公共/私有和登录切换路径；不是所有页面、所有边界的完整人工验收。
- 尚无真实模型配置。失败路径和受控工具可检查，不等于真实自然语言问答已经完成。
- 原交付记录的完整备份恢复，本轮未在新的空集群再次演练；本轮的副本恢复使用本机已有角色，不能用它证明换机器无需准备角色。
- Phase 9、自定义因子回测及远程提交仍未实施，符合当前已说明的边界。

后续如需宣称整个 Phase 8 全部完成，应补齐完整人工演示及空环境恢复等退出条件，而不是移除这些条件。
