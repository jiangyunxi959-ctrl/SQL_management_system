## 3. 因子功能

### 3.1 公共预定义公式与个人私有公式

所有登录用户可查看、运行公共定义，复制后可保存为自己的私有版本。个人私有公式仅本人可见、可修改、可运行；使用公共公式产生的个人运行记录和结果仍是私有的。

第一批 10 个公共因子覆盖成交均价、日内和隔夜收益、日高低价幅度、20 日动量、均价偏离、量比和波动程度。来源、精确公式、所需数据和改编说明见 [公共因子目录](D_公共因子目录.md)。明确的字段、语法、窗口、单位和权限规则见 [表达式规范 v1](D_因子表达式规范.md)，该规范优先于本文的概括。

参考资料主要需要分钟或逐笔数据。本项目用日线改编的指标单独命名，不声称完整还原供应商结果；没有数据的盘口和竞价因子暂不实现。日终结果只用于之后的交易决策。

### 3.2 公式组合

用户从允许的字段和运算中组合公式，例如“收盘价相对 20 日均价的偏离”“最近 20 日的总成交额除以总成交股数”。保存时，同时展示中文解释、单位、所需历史长度和可用日期。

实现边界：

- 只允许字段、常数、加减乘除，以及受限的求和、均值、向过去取值等操作。
- 第一版每条路径最多一个窗口加一次向过去取值，允许计算排除当天的历史均量，不允许窗口套窗口；总输入最多 252 个交易日，表达式最长 1,024 字符、最多 32 个节点、深度最多 8。
- 输入解析成固定结构后校验；合法字段映射到预定义列，数值用参数绑定。原始表达式文本不直接交给数据库执行，不使用 `eval`。
- 第一版不引用其他自定义公式，避免循环依赖和隐藏版本变化。
- 区分原始价格和经过除权调整的价格。原始 VWAP 不能直接与调整后收盘价相除；跨口径表达式保存时拒绝。
- AI 只调用“使用某个已批准公式”的工具；发布、修改公式由登录用户操作并记录，AI 不直接创建可执行数据库对象。

### 3.3 数据与时间边界

- 通过 A 的受限历史查询取数，不能直接绕过日期限制读取全部行情。
- 窗口按交易日历构造；休市日不算一天，交易日缺一条记录不能用更早记录凑满窗口。
- 完整窗口内的停牌日只有在存在可靠的零成交记录时才计为零；缺记录仍是缺数据。
- 分母为零、历史不足、缺数据分别返回空值及原因，不填成 0。
- 第一版 20 日原始价格公式跨除权事件时不给出可比较的因子值，返回 `CORPORATE_ACTION`。单日原始 VWAP 正常计算。
- 计算只使用截至研究日期已知的输入。若后来修改了过去行情，旧结果要么读取保留的结果，要么先恢复原始输入；仅有摘要不能恢复数据。

### 3.4 建议关系表

以下是拟新增对象，不是已经建立的表。

| 对象 | 主要字段 | 约束和用途 |
|---|---|---|
| `factor.definition` | factor_id、owner_id、name、visibility、created_at | 因子归属；同用户同名唯一；SYSTEM_PUBLIC 与 USER_PRIVATE，公共代码全局唯一；普通用户不能发布公共定义 |
| `factor.version` | factor_id、version_no、expression、normalized_tree、unit、price_basis、lookback、created_at | 因子与版本联合唯一；已发布版本不可改写，修改产生新版本 |
| `factor.run` | run_id、owner_id、factor_id、version_no、as_of、universe、input_digest、engine_version、status | 一次运行绑定明确版本、用户、历史日期、股票池和输入；版本使用联合外键，避免错配 |
| `factor.value` | run_id、stock_code、trade_date、value、quality_status | 联合主键防重复；数值只能有限或为空；每条结果可解释缺失原因 |

发布版本、计算结果和完成标记在受控事务中写入。计算失败不能留下“已经成功”的半套结果；失败请求另外留下记录。

结果以固定版本查询，不能通过“最新公式”覆盖过去运行。索引首先按本人运行列表、运行内股票与日期两个访问方式设计；用执行计划核对，不为了数量堆索引。

## 4. 数据库权限与登录衔接

### 4.1 基础分工

| 角色 | 允许 | 禁止 |
|---|---|---|
| 普通应用 | 使用本人公式、运行结果和 C 的受控交易入口 | 直接改交易账本；读取他人私有公式与结果 |
| AI 查询 | 使用获准的历史查询及公式结果查询入口 | 原始表、任意 SQL、改身份日期、直接下单、修改公式、修改记录 |
| 数据导入 | 导入基础资料，完成后让相关旧计算失效 | 操作用户模拟资金和删除操作记录 |
| 审计查看 | 查看获准范围的操作记录 | 修改业务数据、修改或删除记录 |
| 对象所有者 | 安装和维护数据库对象 | 不作为页面、AI 的日常连接身份 |

沿用现有角色，新增授权集中到 D 的 SQL 中；确需独立记录失败请求时，可以增加仅能调用追加记录函数的专用写入身份。

### 4.2 必须做实的边界

- 从真实登录会话取得用户身份，替换当前演示用户编号框；身份不是用户提交一个数字就算成立。
- `app/db.py` 继续兼容 C 已约定的 `user_id/as_of/read_only/role`；身份、日期只在当前事务生效，异常退出也要清理。
- 模型和浏览器不持有数据库密码，也不获得自由 SQL 执行入口。数据库自定义会话变量可被连接持有者修改，因此不能把“设置了 user_id”当成独立身份认证。
- 普通数据库角色做实际越权测试；管理员、表所有者通常能绕过逐行过滤，不能用管理员测试后宣称用户隔离通过。
- 因子定义、版本、运行与结果都按所有者检查。公开内置公式可见，不代表其他人的私有运行结果也公开。
- 提权函数固定安全搜索路径，默认撤销 PUBLIC 调用权；每个入口自行验证用户和对象归属。
- 查询限制返回条数、股票数、日期跨度和执行时间。第一版建议输出最多 100 只、历史窗口最多 252 日、单次计算超时 5 秒；以实测调整，不承诺任意规模都在这个时间内完成。

## 5. 操作记录与失败留痕

推荐分别保存两种事件，避免“操作失败连记录也一起撤销”：

1. `audit.request_event`：请求开始、成功、失败、被拒绝等追加事件。由可信服务使用独立连接保存，支持只读查询和业务回滚后的失败留痕；只有提交结果确知后才写成功。不确定是否提交时记为待核对，不能猜成功。
2. `audit.business_event`：公式发布、账户关键变更等业务事件，与业务修改在同一事务中追加。业务撤销时该业务事件也撤销，另有请求失败记录说明尝试发生过。

记录关联用户、请求编号、研究日期、工具名、公式版本、对象编号、结果条数、耗时和错误类别。拒绝和失败均可追踪；未完成请求能单独查出。敏感凭据不入日志，错误返回不泄露数据库密码或内部连接信息。

普通应用和 AI 不直接更新、删除记录；触发器拒绝原地更改。需要更正时追加新事件，保留原记录。这里保证的是应用角色下的只追加保护，不能宣称能抵抗数据库超级管理员篡改。

Agent 会话表关联真实用户，调用记录关联会话和请求。不要仅保存问答文字而漏掉实际使用的日期、公式版本和查询结果依据。

## 6. 与 A、B、C 的衔接

- A 的历史查询及原五个工具保持兼容；D 新增独立的公式查询和选股入口，避免更改 A 现有返回列。
- B 的原行情和固定指标继续复用，D 不重写同一套均价与收益率计算。
- C 现有三个模板保持可运行。第一版让因子结果形成选股名单、进入模拟交易流程；若增加 C 的自定义因子回测，需要显式增加模板并把公式版本写进回测记录，不冒充已经接入。
- 新增因子计算不能自动触发下单。模拟下单使用可信用户操作和 C 原有资金、持仓检查。

拟新增 `sql/70_factor.sql`、`sql/80_security_audit.sql`、`sql/90_agent_gateway.sql`，以及 D 的连接、登录和受控调用服务。建表顺序与现有按编号加载的工具兼容；SQL 同时提供对已有 A/B/C 库的非破坏安装入口。

## 7. 验收与答辩演示

### 7.1 必做检查

| 目标 | 检查方式 | 通过标准 |
|---|---|---|
| 公式算得对 | 人工小样本与已有 20 只真实股票，独立重算 | 数值一致，缺失原因一致 |
| 历史边界正确 | 修改研究日后的行情，保持研究日不变 | 过去的计算结果不变 |
| 交易日窗口正确 | 加入周末、停牌和缺一日记录 | 不把休市日当交易日，不用更早数据填缺口 |
| 公式输入受控 | 未知字段、未来取值、恶意语句、过深公式、除零 | 明确拒绝或返回有原因的空值；无额外数据库操作 |
| 用户隔离 | 两个真实应用用户互查公式、结果、账户 | 私有内容不可见，写入被拒绝 |
| 连接无残留 | 同一连接依次处理不同用户与日期，包含异常退出 | 前一个请求身份和日期不影响后一个 |
| 失败也有记录 | 查询超时、参数错误、越权、交易回滚 | 业务数据保持正确，失败尝试仍可追查 |
| 记录不可随意改写 | 用普通应用和 AI 身份修改、删除记录 | 数据库拒绝 |
| 与现有系统兼容 | 重跑此前 ABC 的全部检查 | 原检查继续通过 |

### 7.2 一段完整演示

用户甲登录，保存“收盘价高于当日成交均价”的公式，选择过去日期并运行；页面显示公式版本、依据、计算结果和缺失原因。切换用户乙，看不到甲的私有公式。尝试提交不允许的公式，被拒绝并留下记录。回到甲，把公式改成第二版，旧运行仍对应第一版。最后查看这几次操作记录和受控模拟下单结果。

这样能连续展示建模、计算、约束、权限、事务与操作记录，且每一步都有数据库证据。

### 7.3 可选查询效率展示

只在功能通过后比较“每次从行情重算”和“读取已保存且输入未变的结果”。同一数据、同一公式、同一输出，先确认结果一致，再重复测量并报告中位数和执行计划。现有样本只有 9,700 行，不预设明显加速；不通过虚构数据规模或只挑最快一次制造效果。

缓存键必须包含公式版本、用户或可见范围、研究日期、股票池、计算版本和输入标识；基础资料变更后不能继续把旧结果当成最新结果。保存的旧结果仍可作为当时运行的记录。
