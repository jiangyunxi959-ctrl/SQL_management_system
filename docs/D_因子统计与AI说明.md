## 本次新增的统计

公共公式和私有公式计算后，都可查看本次运行的统计。对象是某个日期、某份股票池、某个固定公式版本的一组因子值。

- 股票总数、有效数量、缺失数量、有效比例。
- 均值、中位数、最小值、最大值、样本标准差。
- 5%、25%、75%、95%分位数，中位数对应50%分位数。分位数采用线性插值。
- 正值、负值和零值数量。
- 缺数据、停牌、零成交、历史不足、除权等原因的数量。

统计直接由 PostgreSQL 对已保存结果聚合，页面不把全部结果下载后自行算均值。查询沿用本人运行的权限，不允许通过别人的运行编号读取统计。

只有有效有限数进入数值统计，缺失不补零。没有有效值时均值、分位数和标准差为空；只有一个有效值时样本标准差为空；全部数值相同且至少两条时标准差为零。异常的无穷数也被排除并统计为异常结果。

一个股票可以同时有多个缺失原因，所以各原因数量相加可能超过缺失股票数。页面筛选不改变整次运行的统计，统计标题固定显示实际运行、公式版本、日期和股票池，避免误以为切换了日期就重算了旧结果。

这类统计描述因子的数值分布，不说明因子一定能预测涨跌。预测能力、未来收益相关性、分组收益等需要另行定义研究区间、未来收益、费用及无未来信息的验证流程，不应和本次分布统计混为一谈。

## 目前 Agent 到底是什么

当前项目的 Agent 是受控工具调度层，负责把一个合法操作交给已有查询或计算服务，并检查用户、日期、允许的参数和访问范围，留下记录。它拥有的工具包括历史查询、因子目录、因子运行、结果查询，以及本次新增的 `factor_statistics`。

**目前没有真实模型，也没有真正的自然语言 AI 问答。** `ScriptedModel` 是检查用的固定指令替身，`UnconfiguredModel` 会明确报告尚未配置。不能把工具代码存在解释成真实 AI 已接入。

## 接入模型后，AI 应体现在哪里

例：用户说“看一下我刚算的20日涨幅，多少只有效，分布偏不偏，有没有因为停牌没算出来的？”

1. 模型理解问题，识别所指的本人运行；信息不足时询问日期或运行记录，不猜编号。
2. Agent 校验身份与允许的调用，使用 `factor_statistics` 查询这个运行。
3. 数据库返回真实数量、分位数、均值、标准差和缺失原因。
4. 模型基于这些返回值用中文解释，并给出具体运行、日期、版本作为依据；不能凭空编数字。

模型负责理解和解释，Agent 负责执行流程与边界，数据库负责资料、数值计算和权限。模型不能自由执行 SQL，也不能因用户一句话越权查看别人或直接下单。

真正完成这部分还需要：配置实际模型服务、添加自然语言入口、实现模型提出调用—工具返回结果—模型解释结果的闭环，以及错误/超时/多轮调用上限的检查。本次新增统计工具已可由现有受控调用层使用，但没有偷偷接入外部模型或上传项目数据。

## 验证入口

`tests/d/test_factor_statistics.py` 覆盖手算分布、多原因、无样本、全部缺失、单值、常数、非有限值和跨用户拒绝；页面与既有受控工具检查一同回归。计算结果和界面分别核对，不以只有服务代码作为完成依据。

## 本次实测记录

- 新增 8 项统计检查；与工具和前次修复检查合计 16 项通过，13 个 SQL 检查及 EMA 对照通过。
- 全量 D 初跑为 54 项通过、1 项页面检查失败。原因是测试在首次登录绑定前预设了运行选择，被正常的换用户清理移除；测试改为先绑定身份，再加载本人运行，相关 16 项重新通过，没有放松用户切换清理规则。
- 在独立真实行情副本的 10 个运行上，对各 20 只股票的统计与 Python 独立计算核对，一致。该股票池为固定验收样本，不是实际历史指数。
- 实际浏览器使用验收甲，在 2025-05-30 的教学股票池计算当天成交均价：19 条结果全部有效，页面显示均值、中位数、样本标准差和分位数。
- 本次没有改动数据库结构，没有重新计算或覆盖旧运行，也没有接入外部模型。
