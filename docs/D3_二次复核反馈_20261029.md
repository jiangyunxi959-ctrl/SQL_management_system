## 1. 三个失败场景

| 复核项 | 处理 | 本方检查 |
|---|---|---|
| 3.1 研究日 2025-05-30 仍能评价到 2025-06-04 | 提交、读取、比较都使用调用方传入的研究日。结束日或开始日晚于研究日时，`start_evaluation` 直接拒绝，不插入评价。工具在进入服务前也会拒绝。`report` 对超出研究日的已有评价拒绝读取 | `tests/d/test_d3_binding.py::test_evaluation_cannot_pass_the_research_date`：越界调用后，该用户的评价行数仍是 0 |
| 3.2 本金 10 万和 20 万返回同一个回测编号 | 请求摘要包含本金、股票池、起止日、研究日、策略版本、费用版本、引擎 `d3.3` 和 `research.fn_data_version()`。换本金得到新编号。显式提交编号对应另一套内容时抛出错误，不返回旧编号 | 同文件 `test_changed_cash_does_not_reuse_the_old_backtest` |
| 3.3 取消后仍被写成 COMPLETED | 评价发布和回测发布都在同一事务里 `SELECT … FOR UPDATE`。状态不是 `RUNNING` 就不写结果。随后的完成更新带 `WHERE status='RUNNING'`；更新不到行就抛错，整段插入回滚 | 同文件 `test_cancel_is_not_overwritten_by_publish`：先 `cancel_eval`，再调用真实的 `_publish_evaluation`，状态保持 `CANCELLED`，因子值行数是 0 |

回测最终发布使用同一把锁。退出登录仍把本人 `RUNNING` 的评价和回测改成 `CANCELLED`。同一提交编号已经是 `RUNNING` 或 `COMPLETED` 且摘要一致时，不再另起一条计算线程。

旧引擎算出的完成记录留在原行，不改状态、不改编号。新请求的摘要带 `engine=d3.3`。摘要或引擎对不上时，不能沿用那个提交编号。

## 2. 同时补上的约束

- 数据指纹走 `research.fn_data_version()`。它按行情条数、收盘价合计、除权因子、证券和交易日历做 32 位摘要，不把整表收成一个 JSON。评价和回测行保存 `engine_version` 与 `data_fingerprint`。
- 成交前调用 `research.fn_execution_block`：停牌或无成交量、未上市或已退市、上市前五个交易日、信号日之后到成交日之间的除权、涨停不买、跌停不卖。这不是把新回测改接到 `sim.fn_advance_day` 和 `sim.cash_ledger`。个人费用仍记在 D3 自己的成交和分项里，避免再加一遍全库 `ref.fn_fee`。
- 策略页可以选择持有只数或前百分比。服务里本来就有前百分比。
