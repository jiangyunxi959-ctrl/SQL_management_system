## 1. 目标、范围和完成条件

把现有公共/私有公式接成一条完整流程：评价与随后收益的关系 → 分组观察 → 创建本人因子策略 → 设置本人费用 → 回测和毛净收益对照 → AI基于实际结果解释。另完成一个独立真实资料集里的结构化外部财报接入。

必须实现：IC/Rank IC、覆盖与分组、单因子策略、私有费用版本、A股与自定义maker/taker费用模式、同成交毛净结果、独立零成本对照、受控AI研究工具、统一页面及外部财报样例。图表与财报空表修复已经完成，不能退回旧显示。

不扩展：多因子优化、自动调参、实际证券下单、完整加密资产撮合、盘口重建、融券卖空、任意公告全文抓取。自定义maker/taker仅改变收费假设，不能宣称新增了另一个市场的交易规则。

完成必须同时满足：计算与手算一致、无未来信息进入信号、资金与逐笔费用对账、本人数据隔离、原ABC/D2功能回归、真实DeepSeek闭环、实际浏览器操作及备份恢复。不能仅以页面存在或测试替身通过宣布完成。

## 2. 统一计算契约

### 2.1 时间与数据

- 用户在界面选择评价范围和评价截止日；服务端锁定。信号日期上限不晚于截止日；后续收益的退出日期也不能越过截止日。
- t日因子只读取t日日终可知的数据和t日历史股票池。日历用当前资料集的交易日序列，不用自然日加减或今天的成分股回填。
- h取1/5/20，标签为 `adjusted_close(t+h) / adjusted_open(t+1) - 1`。h=1为下一个交易日开盘至收盘。t+1/t+h按交易日索引定位，不能遇停牌就向后寻找更有利的价格。
- 因子取数和标签取数分开。后台服务可以逐日设置受控事务研究日；模型不能提交或更改身份、角色、研究日上限。标签绝不进入选股接口或策略候选数据。
- 缺因子、缺起止价格、起止日停牌、退市无明确退出价值、历史不足、标签尚未到期、除权口径无法一致等分别留原因。缺失不是0，也不擅自延长持有期。
- 研究样本默认t日可投资的历史成员；以后退市的股票不能因当前不在库里而被提前删除。无法处理的终止价值必须影响覆盖说明。
- 教学行情、真实行情与财报必须在独立资料集或副本中使用。不能凭相同股票代码把真实财报混进SYNTH行情。
- 固定数据快照、公式版本、表达式摘要、引擎版本和股票池摘要。原数据补录或更正后，旧结果不静默变化。

### 2.2 IC、分组和样本边界

- 每天按股票代码对齐有效因子值和有效标签。IC是原值Pearson；Rank IC是两边平均秩的Pearson，平值用平均秩。
- 每日最低有效配对数10；任一序列零方差、样本不足时结果为空并记录原因。算法内部允许较短数组作单元手算，正式服务必须执行10只门槛。
- 汇总只使用有效日期，均值、样本标准差、IC正值比例及非年化ICIR分别给出有效天数。少于两日时标准差/ICIR为空；标准差0时ICIR为空，不返回无穷。
- 默认5组且每组至少5只；若不足25只但至少15只，则实际使用3组。不足15只时不分组。将实际组数、每组数量和降组原因保存，不在后台悄悄变更。
- 分组按因子升序，组1低值、最高组高值。边界不拆相同值，按完整平值块寻找每组至少5只的可行分割，使各组人数相对N/G的平方偏差之和最小；并列选较早切点。若5组不可行降3组，3组仍不可行则不分组，记录TIED_GROUPS/SMALL_GROUP。
- IC保留因子原始方向。策略的“高值优先/低值优先”独立保存；方向调整后的诊断必须另有标签，不能看完测试结果后自动翻转IC。
- 每组展示该批股票的h日等权平均标签与数量，高低组差是理论比较，不是可交易的卖空组合。重叠h日标签不能直接逐日复利成净值曲线；累计分组对照只能用预先规定的不重叠批次，并明确调仓和持有方式。
- 不对重叠标签或小样本输出未经验证的显著性判断。训练/验证/测试日期预先划分；不自动搜索最优窗口。

### 2.3 策略与费用

- 单因子、等权、long-only；支持Top N或前百分比，百分比按有效候选数向上取整，最多20只，不超过实际有效数。平分以股票代码稳定排序；无有效候选默认保留原持仓且不新增，必须可见记录。
- 首个信号在start日收盘；日调仓每个信号交易日执行，周/月调仓取历史日历中当周/月最后交易日，执行在下一个交易日开盘。没有下一交易日或执行超出end时不下该批订单。
- 每一交易日仍要更新估值；非调仓日不能跳过费用、公司行动和净值记录。卖不出去的旧持仓不能在目标表里假装已消失。
- 不得按下一开盘的真实价格倒推t日目标手数。t日用当时可见价格和费率预估形成委托；下一日按真实价格与费用检查，资金不足时按事先固定规则拒单或减少整手，并留痕。初版建议沿用现有拒单机制。
- A股模式保存买卖佣金、最低佣金、包含关系和滑点。税费按成交日及冻结的规则快照应用；用户不能改全库税费或覆盖别人的方案。
- CUSTOM_LIQUIDITY模式明确是费用模拟：maker/taker费率、统一假设ALL_TAKER（默认）或ALL_MAKER；不按买卖方向猜测，不声称从日线识别真实流动性。不实现返佣或部分成交分拆。
- 费率存小数，界面输入单位明确；1基点=0.0001，万三=0.0003。费率初版范围[0,0.1]、滑点[0,1000]基点、最低费用非负且有上限；禁NaN/无穷。这些是项目输入限制，不是市场规则。
- 两种模式各自声明税费包含关系，不能同时启用两套完整手续费。既有默认佣金/税费已经扣过，新增路径必须替换本次适用的计算入口，不能二次扣费。

## 5. Phase 2：费用服务、版本与会计接入

建议 `app/costs/{contracts,service,calculator}.py`，共享一个纯费用核算器与受控数据库入口；账本的实际写入仍走交易服务。先做费用，后接因子策略，避免两套回测成本不一致。

工作：

- 私有方案创建/新版本/读取/归档；运行固定具体版本，后改费率不改变旧运行。对系统税费保存适用历史规则快照，来源及截止时间可核对。
- 更新资金冻结、预估可买手数和执行日校验，使三处使用一致规则；将 `research.fn_step` 中类似 `unit*1.002` 的假设移入统一核算，不让高费率账户透支。
- 成交后先确定实际价和金额，再逐项舍入现金费用、一次更新现金/持仓/成交/费用分项/流水；异常整体回滚。拒单/撤单无成交费用。
- 滑点以买入更高、卖出更低的价格体现；满足价格精度、限价、涨跌停和成交边界。不能既改变成交价又从现金另扣一次滑点。没有日内路径时不把“日高低价覆盖了限价”当作已证明成交。
- 新费用必须由服务端绑定本人账户/运行，不接受模型自由传费率字典。旧 `ref.fn_fee` 保留兼容；不更改全局默认规则来模拟个人优惠。

通过：默认模式与旧引擎逐笔一致；零费、最低费、不同买卖费率、两种自定义费率假设、参数单位、资金不足、舍入、重复请求、取消和并发均有测试。现金/持仓/冻结额对账无差异。

## 6. Phase 3：因子评价服务与独立数值核对

建议 `app/factor_research/{contracts,labels,metrics,service}.py`。复用已有表达式验证、编译和历史面板，不另写一套因子语法。

先独立实现并手算验证Pearson、平均秩Spearman、分组及汇总；再落库。SQL负责安全取数、配对与可行的聚合，Python可组织评价，结果保存中间数量和摘要以便解释。若使用数据库corr，仍用独立Python作对照。

后台按信号日调用t时点面板；标签使用独立、受截止日限制的读取。可以复用本人已保存因子运行，但必须匹配完整公式版本、日期、池、数据快照。不能把今天改过的数据和旧运行混在同一评价。

初版限100只、126个信号交易日、3个horizon、至多50000条配对。长作业后台运行，单查询5秒目标、总作业180秒硬上限，阶段进度/取消/失败原因可见。先测性能，不通过无限拉长超时掩盖重复查询；超界明确拒绝，不静默截断。

通过：正/负完全相关、平均秩平值、零方差、缺失、末端未到期、节假日、除权、退市、历史池变动、用户隔离和中断恢复均核对。每个horizon都有逐日覆盖和无法计算的理由。

## 8. Phase 5：毛净利润与独立零成本对照

定义同成交毛权益 `gross_same_fills(t) = net_equity(t) + cumulative_cash_fees(t)`，前提为同一成交序列、无外部资金流。除初始入金外如未来允许其他资金流，需单独做收益归因，不能直接套公式。

展示三条口径，不混称：实际计费净值、同成交毛净值、可选独立零成本回测净值。第三条用独立账户重新撮合，使用相同策略、信号范围和数据快照，但数量与拒单可能不同。不能用第二条代替第三条。

所有利润默认是按市价估值的账户利润，仍含未平仓资产。单独清算会产生额外价格与费用，不能把当前权益称为全部卖出后的到手金额。最大回撤分别对各条曲线按各自历史峰值计算。

通过：毛净差等于实际累计现金费用；分项和等于成交总费，成交总费和等于账本收费；不重复算滑点；零成本独立账户可因资金门槛产生不同手数。每条曲线共享日期但各有口径标识和自适应纵轴。

start/end用于限定评价任务，不允许修改固定研究日；普通查询工具仍不能传as_of。新工具Schema、本地校验和调度注册表同时更新，所有访问重查身份和归属。后续数据标签不加入聊天证据，默认只外发聚合评价摘要和必要的公共定义；不把个人资产、订单、佣金配置全文或整张财报发给外部模型。成本工具外发只保留必要的汇总影响，不暴露本人完整费率方案。

长评价可能超过现有90秒模型回合上限，工具返回RUNNING+job_id后正常结束本轮；界面等待作业完成后由用户继续请求报告。不要增加模型轮询风暴或把模型预算改成无限。费用设置、策略保存和回测启动通过页面确认，模型不持有可重放的写入授权。

系统提示词追加金融研究规则：区分分布/预测、原始/排序IC、小样本/显著性、标签/信号、理论分组/实盘可成交、同成交毛利润/独立零成本；说清日期、费用假设和证据，不能挑最好区间或把成本前盈利说成净盈利。用户个人提示词只能改变解释侧重，不能改权限和评价口径。

通过真实DeepSeek至少6场景：请求评价并读取结果、比较两种因子、生成周调仓策略草稿、解释成本侵蚀、解释低覆盖/缺失、拒绝未来日期/他人费用/恶意提示词。至少一个场景证明模型读取真实工具返回后继续下一步；异步场景以多轮对话衔接，而非伪造同步完成。

## 11. Phase 8：结构化外部财报的最小真实接入

在真实行情专用副本中复用现有下载/导入器，先选至少2家已有真实行情的公司、2个季度，验证供应商返回口径和必要字段，保留原始文件与hash。不在教学库更新同代码财报。

来源区分PROVIDER_SNAPSHOT与DISCLOSURE。当前采集的供应商快照仅从实际采集日可用，不能为显示2025年财报而改早日期。历史财报策略只能使用有当时可见证据的公告/更正版本。ROE究竟是比例还是百分数、EPS口径、累计或单季收入都必须核对；不能按直觉再乘100。

财报页允许从该真实资料集中已导入的证券直接选择公司，不强制属于研究日指数。行情只到2025年而快照2026年才采集时，允许在2026年的研究日查看财报并分别标注行情截至日；不能因旧股票池已无成员而让所有真实财报永远无法展示，也不能假装2026年有最新行情。

通过：真实下载/导入、重复导入幂等、来源与公告/采集/可用日期展示、更正版本可追踪、当时不可知的值不会出现在旧日期。网络或供应商不可用时保留离线检查并明确真实接入未完成，不能造数据或改标SYNTHETIC来冒充通过。

## 12. Phase 9：全量验收、恢复与交接

运行原C+D、所有D3检查及SQL门禁，失败先修原因，再复测。完整流程的数值以独立Python/手算对照，不用同一实现的结果当期望值。

专用库做备份，恢复到另一个新库，预建最小权限角色；核对费用、策略、评价、成交、净值和AI记录，继续本人旧对话/新任务。检查甲乙不可见，密钥不在Git可见文件，文档结构和链接检查通过。

更新README_D、README_D_HANDOFF、D3实现验收、D3课堂演示及worklog。交付中清楚区分实际通过、离线通过和外部条件未满足；真实联调不能用测试替身代替。默认不推送远程、不擅自改部署。

## 13. 最小手算样例与失败条件

| 样例 | 正确期望 |
|---|---|
| 因子1至10，标签0.01至0.10 | IC与Rank IC均为1；标签反序则为-1 |
| 全部相同因子值 | IC/Rank IC为空，原因零方差；不能显示0 |
| 配对不足10或退出日在截止日后 | 正式IC不计算，分别记录样本不足或未到期 |
| 平值因子、标签 | 平均秩对照一致；分组不拆同值；不足条件时降组或不分组 |
| 19个互异有效值 | 只能3组，不能把5组各3/4只说成满足每组5只 |
| 10000元买/卖，示例佣金万三最低5元、双边过户万分之0.1、卖方印花税万五 | 买费5.10元、卖费10.10元；这些是固定测试规则，不宣称当前所有市场费率 |
| 初始10000，买100股×10，卖100股×11，使用上行测试规则 | 买费5.01、卖费5.56，总费10.57；同成交毛利润100、净利润89.43，最终现金10089.43 |
| 资金1005元欲买100股×10，同上规则 | 实费1005.01元，不足，应拒绝；零成本对照可成交 |
| maker/taker假设切换 | 使用对应单一费率，不根据买卖方向转换；不与A股完整佣金重复相加 |
| t日收盘信号 | 任何t日成交、以t+1价格参与t日排序或手数决策都判失败 |
| 改个人费率或公式新版本 | 旧结果/旧费用/重放快照不变，甲不能引用乙的新版本 |

实际税费来源与适用日期按总体设计和届时核对记录管理。本计划的数值仅是可重复的会计测试夹具，不是最新市场费率建议。
