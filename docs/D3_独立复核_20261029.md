## 2. 必须修复的正确性问题

### 2.1 因子评价与策略使用了伪造字段（阻断）

位置：`app/factor_research/service.py:70–92`、`app/backtest/factor.py:112–125`。

两个流程只读后复权开盘/收盘，随后把volume、amount设为1，把高低价设为收盘，把原价也设成后复权价，且固定ca_in_window=false。因而大量公共公式已改变含义：VWAP变成1、振幅变成0、量比变成常数，除权保护也失效。

独立复现：在2025-05-28、SYNTH300运行 `amount / volume`。原数据库因子引擎给sh.600001为13.1192、sh.600003为14.5192、sh.600004为15.2192；D3评价均存成1，19条全部不一致。任务状态仍为COMPLETED。

修复：评价和策略必须复用既有时点面板与权威因子计算，使用真实OHLC、金额、股数、交易日序列、缺失/停牌/公司行动信息。以所有50项公式作逐股票、逐信号日对照，不能只用close_hfq测试。

### 2.2 新回测另建了撮合路径，滑点没有进入现金（阻断）

位置：`app/backtest/factor.py:108–198`，尤其146–161行。

该路径未使用原C的订单/成交/资金账本和约束，而是维护Python字典。它先用未加滑点的价格计算amount并扣现金，之后才把滑点后的quote.price保存为成交价。即使零滑点，价格保留精度与金额也可能不一致；同时把后复权价格拿来作现金成交，不能代替真实报价和公司行动会计。

独立复现：同一策略把滑点从0改到1000基点，两条净权益曲线完全相同，末值同为100185元。有滑点成交保存3700股、价格28.99元，金额却为97510.91元；按记录价格应为107263元。初始仅10万元，正确资金检查本不应允许这笔买入。

修复：先确定合法实际成交价，再按数量计算金额、费用和资金，保持数量×价格=金额；接入原撮合/账本的停牌、涨跌停、限价、整手、可卖数量和资金约束。D3交易与账本不能各维护一份互不校验的资金。回归以真实撮合核对，不再只测试独立的round_trip_cash夹具。

### 2.3 AI评价工具能越过固定研究日（阻断）

位置：`app/agent/tools.py:299–302`、`app/factor_research/service.py:22–30`。

工具直接把模型给出的start/end交给评价服务，未校验end不晚于可信ctx.as_of；服务也没有独立的固定截止日。普通历史行情工具虽然有日期检查，不能代替新工具自身检查。

独立复现：会话研究日固定2025-05-30，模型请求评价至2025-06-04。工具接受，作业COMPLETED，存出76条退出日超过5月30日的非空后续标签。当前工具报告还可能把它包装成5月30日上下文。

修复：UI/工具/服务共同使用服务端可信评价截止日。任务开始、结果读取及跨评价比较均检查日期、池、标签和快照，不允许通过已保存的未来评价绕过限制。合法历史标签可晚于信号日，但必须不晚于用户锁定的研究截止日。

### 2.4 更改资金会误用旧结果，且没有真正的数据快照（重要）

位置：`app/backtest/factor.py:64–71`；`app/factor_research/service.py:29–50`。

默认回测幂等摘要漏了cash和universe等影响结果的参数，命中后直接返回旧COMPLETED运行；评价snapshot字段也只是参数摘要，没有冻结输入数据或纳入数据指纹。新运行无法据此证明重放的是同一份数据。

独立复现：同策略、同区间、同费用，第一次请求100000元，第二次请求200000元，两次均返回bt_id=25，没有重新计算。

修复：规范化完整请求并绑定资金、池、全部版本、快照/引擎等；同请求编号但内容不同必须拒绝。数据变化不能仍把旧结果标为新结果。并发和中断重试同时防止重复写成交/净值。

### 2.5 结束日净值被跳过（重要）

位置：`app/backtest/factor.py:162–173`、190–197行。

结束日进入调仓分支后发现没有下一个交易日，就continue跳过当天curve.append。最后一天的估值因此丢失。

独立复现：要求2025-05-30结束，保存的最大净值日期却为2025-05-29。应停止生成次日订单，但仍记录本次范围内最后交易日的持仓估值、资金和费用；不需要假想清仓。

### 2.6 旧费用/策略版本仍可改（重要）

位置：`sql/migrations/d3/001_research_cost.sql:128–149`、220–266行。

表注释说“不可变”，但own_all对本人授予UPDATE/DELETE，没有版本冻结触发器。已绑定旧运行的版本字段可被修改，而运行依旧指向同一个版本号。

独立复现：普通app_user在本人上下文下，把已用于回测的费用版本slippage_bps从1000更新成0，数据库接受；本轮探测已回滚。

修复：费用和策略版本实施数据库级不可变约束、允许受控新增版本；运行保存并核对固定内容摘要及规则快照。不能只把界面保存按钮改名“新版本”。

## 3. 按原计划尚未完整兑现的功能

以下为代码/页面检查结论，不与上面的独立数值复现混称：

- 公共公式不能直接进入研究或策略，页面只保留USER_PRIVATE；前百分比仅有表字段，创建接口和页面只支持Top N。
- 评价组数和组收益已落表，但研究页只展示分组数，没有组收益/成员展示；没有汇总Rank IC及覆盖原因视图，明细只取前20行而不提供完整浏览。
- 新回测没有原C的资金账本、规则快照、手数完整预估、信号/目标记录或对应重放入口。保留原C页面不等于新回测遵守了原C规则。
- 费用配置是单一佣金率和用户自行填写税费率，没有兑现买卖不同佣金、包含关系及按成交日规则快照。旧版本内容也未冻结。
- 因子回测仍在页面同步执行，没有可操作的专属取消；D2聊天取消不能证明D3评价/回测取消和退出后停止已完成。
- 评价直接创建daemon线程；没有180秒总预算/有界队列/完整断点状态，超过100只默默截断。进程启动函数用管理员批量中断全库RUNNING任务，多进程部署可能误伤另一进程正在运行的任务。
- 比较评价工具只返回same_universe布尔值，未实际阻止不同日期/标签/快照直接比较；策略草稿工具直接回显参数，未校验引用公式的可见性和版本内容。
- 实现方明确记录的小样本真实模型回答未通过，这是接口/证据适配问题，不是“缺少外部条件”。修复时不得通过放松数值校验来掩盖前述错误。

## 4. 确认已做成的部分

- 新增导航、费用方案版本创建、基础IC/平均秩算法、私有对象的基本行权限、理论分组落表等代码确实存在；已有97项测试可重新通过。
- 独立零成本运行使用单独运行记录，并非简单把原净值加费用；但其共用的模拟器还不正确，所以不能据此认定对照数值可信。
- 真实资料副本中存在sh.600000、sh.600004两公司各2024Q2/Q3四条BAOSTOCK记录，类型PROVIDER_SNAPSHOT，可用日2026-10-29。独立查询：2025-12-31看不到，2026-10-29看到4条。教学副本仍是22条SYNTHETIC记录，没有混入这些快照。
- 快照不冒充历史公告的处理正确；没有完整公告版本，不能据此做当时可知的历史财报策略。这是当前数据范围限制，应保留。

## 5. 建议修复顺序和重新验收条件

1. 先恢复统一真实因子面板与原C撮合/资金账本，修复字段、真实成交价、滑点、金额和末日估值；在此之前不扩AI问法或美化收益图。
2. 补服务端截止日、完整请求绑定、数据快照、不可变版本及异步任务/取消管理。
3. 用本轮样例新增不会被测试替身或数学夹具替代的集成检查：50公式真实输入对照、资金/成交对账、滑点影响、不同资金/池不误用缓存、末日估值、未来日期无写入、旧版本更新被拒绝。
4. 再补公共公式、前百分比、分组展示、覆盖/Rank IC、策略参数确认与重放，按原D3计划点完真实流程。
5. 最后再做真实DeepSeek全场景，要求所有已约定场景通过且证据来自修正后的计算；重跑97项及新增检查、SQL门禁和恢复验证。

本轮没有对应用做大规模修补，也没有更新原97项的断言来隐藏问题。原自检说明的测试数量可以保留，但不能再作为“D3完整通过”的依据。
