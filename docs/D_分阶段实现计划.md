## Phase 1：把表达式规范变成可执行的规则

### 建议文件

`app/factors/lexer.py`、`parser.py`、`types.py`、`validate.py`、`errors.py`；`tests/d/test_expression.py`、`test_units.py`、`test_temporal_rules.py`。

### 执行内容

1. 词法分析严格匹配文档，不直接借用 Python 语法作为产品语言。可用小型手写解析器；不得引入会放宽语法的隐式规则。
2. 保留每个符号和节点的位置，错误返回起止位置、错误类别和中文说明。
3. 规范化结构具有明确节点类型；哈希使用稳定序列化和语法版本。不能将“规范化”作为改变小数精度、运算顺序的理由。
4. 实现字段和函数白名单、参数数量、数字精度、字符长度、节点数、树深度检查。
5. 推导每路径窗口数、lag 数和总历史长度。`lag(ts_mean(volume,20),1)` 与 `ts_mean(lag(volume,1),20)` 都合法；两者需要 21 条输入。
6. 单位用指数表示并组合：原始价格 P、调整后价格 H、股数 Q、成交额 P×Q。乘除合并指数，加减要求一致；同口径价格相除后为无单位。P 与 H 的残留混用拒绝；不得简单使用一个 raw/hfq 标签误拒绝合法无单位收益组合。
7. 单独记录时间支持与数据来源，以便 Phase 5 判断跨除权事件。`close_raw/lag(close_raw,1)` 虽然无单位，仍跨日比较原始价格，需要事件检查；同日价格比值跨日求均值则不同。
8. 为每个公共表达式生成单位、所需输入长度、依赖字段和中文解释，核对目录声明。

### 验收

- 覆盖 10 个公共表达式及规范中全部拒绝示例。
- 检查优先级、括号、一元负号、非法大小写、Unicode 混淆、科学计数法、过长或过深输入。
- 覆盖长度与窗口的合法上界及超界一格；比较和逻辑条件必须拒绝。
- 规范化相同输入稳定；减除运算不交换顺序；单位和历史长度推导符合手算。

### 退出条件

单元检查通过，接口可返回 `ValidatedExpression`，而不是仅返回“校验通过”的布尔值。此阶段不需要数据库和真实模型。

## Phase 2：建立数据关系、权限和非破坏安装入口

### 建议文件

`sql/70_factor.sql`、`sql/80_security_audit.sql`、`sql/90_agent_gateway.sql`；`app/setup_d.py`；`sql/tests/test_d_schema.sql`、`test_d_permissions.sql`；`requirements-d.txt`。

### 数据对象

| 对象 | 必要关系及约束 |
|---|---|
| factor.definition | 公共代码部分唯一索引；同用户私有名称唯一；公共维护者与私有所有者一致性；归档标记 |
| factor.version | `(factor_id,version_no)` 唯一；原文、结构、语法版本、摘要、类型、来源；版本不可原地改写 |
| factor.run | 外键精确引用定义版本；实际运行人、研究日期、股票池、引擎版本、输入依据、完成状态 |
| factor.value | `(run_id,stock_code,trade_date)` 唯一；有限数或空值；原因码和原因明细；完成结果不可改写 |
| core.user_credential / core.auth_session | 引用已有应用用户；密码摘要；随机会话凭证的摘要、有效期、撤销时间；凭据不在普通查询中返回 |
| agent.session / agent.tool_call | 会话与真实用户关联；工具调用与请求编号、参数摘要和对象关联 |
| audit.request_event | 请求编号、事件序号/类型、用户、日期、工具、结果或拒绝原因；仅追加 |
| audit.business_event | 与业务修改同时提交的事件；公式版本、模拟操作等对象关联；仅追加 |

业务状态的具体枚举及完成标记在此阶段固定到数据库约束与服务类型。失败计算的业务写入整体撤销，失败证据存在请求记录；不能留下伪成功运行。若使用 RUNNING 中间态，超时或崩溃必须可识别为未完成。

### 安装与授权

1. D 安装器校验 A/B/C 依赖，在一个事务内安装 D 对象；不重建现有库，不重复执行 B 中会删除依赖对象的脚本。
2. 安装器连续执行两次不重复数据、不覆盖同版本不同内容；后续结构变更用显式迁移。
3. 70 负责因子结构，80 负责身份和记录结构，90 负责最终授权与工具对象；若存在相互依赖，表与函数分步创建，整次安装统一提交。
4. 无登录对象所有者持有表；应用、AI、导入、审计使用受限身份。新增记录写入身份只授予最小追加入口，密码从配置读取。
5. 表和函数默认撤销 PUBLIC；逐个授权。因子定义、版本、运行、结果以及 Agent 会话实施用户过滤。
6. SECURITY DEFINER 固定安全搜索路径，完整限定对象名，并主动核验归属；不能仅凭启用了 RLS 认为所有者函数也受其限制。
7. 开发种子在 seed 步骤加载，不在 D 建表时假设 demo_user 已存在；当前重建器在所有编号 SQL 执行之后才加载样本用户。

### 验收与退出

全新库安装、已有 ABC 库安装、重复安装均成功；已有价格与交易资料计数和内容摘要不变；真实受限身份越权被拒绝，表字段都有清楚说明。

## Phase 4：公共种子、私有公式和不可变版本

### 建议文件

`app/factors/catalog.py`、`service.py`、`models.py`；`sql/seed/d_public_factors.json`；`scripts/register_d_factors.py`；`tests/d/test_catalog.py`、`test_factor_versions.py`。

### 服务接口建议

- `list_definitions(identity)`：本人私有与公共目录，含明确类别和版本。
- `validate_expression(expression)`：只做纯规则检查，不执行 SQL。
- `create_private(identity,name,expression)`、`new_version(identity,factor_id,expression)`。
- `copy_public(identity,factor_id,version,name)`：完整复制内容和来源版本。
- `archive_private(identity,factor_id)`：保留旧运行与旧版本。

### 执行内容

1. 10 个公共定义按目录逐条注册，公共和私有走同一个校验流程。种子内容包含源资料、原名、页码和改编说明。
2. 公共初版为 1；同代码同版本同内容重复安装不新增，同代码同版本内容不同则报冲突。
3. 所有权从身份取得，不由用户传入所有者。普通用户不能把私有 visibility 改为公共。
4. 版本号分配通过锁或约束加重试处理两个并发修改，不使用裸 max+1。
5. 复制后无隐式依赖，原公共版本后续变化不影响私有副本。归档之后旧结果仍能按固定版本查询。
6. 普通应用不能直接插入伪造的 normalized_tree 后跳过解析；入口由可信应用校验，运行时再次校验保存的原文及结构摘要。若数据库负责解析结构，仍须使用同样白名单。

### 退出条件

两用户及 AI 权限矩阵通过；公共定义可读可复制但不可改；私有内容、运行和编号均不能跨用户获取；并发版本不重复；公开名称相同不会导致选错定义。

## Phase 5：数据库计算引擎与可解释结果

### 建议文件

`app/factors/compiler.py`、`execution.py`、`quality.py`、`fingerprint.py`；`tests/d/test_factor_sql.py`、`test_factor_quality.py`、`test_factor_pit.py`；`experiments/d_factors/`。

### 执行步骤

1. 定义运行范围：首版每次一个明确公式版本、一份研究日历史股票池、一个研究日；保存到该日的结果。历史曲线作为有界范围扩展，不悄悄使用今天股票池计算历史排名。
2. 通过 A 的 PIT 股票池确定研究日成员；为这些股票向前取足公式所需历史，不强制它们在整个回看窗口都属于该指数。不得看到未来成员。
3. 从受限 PIT 入口读取 raw/hfq 行情。需要日历和除权元数据时，增加只返回不晚于研究日资料的窄函数，明确授权，不能给 AI 开原始表权限。
4. 构造证券×交易日的稠密骨架，再左连行情，保留缺行。禁止对缺行后的稀疏序列直接 ROWS 窗口，避免错误凑齐 20 条。
5. 从校验结构生成受控 SQL，字段和函数名只来自固定映射，参数使用绑定。向过去取值和窗口分不同 CTE 层，避免直接嵌套 PostgreSQL 窗口函数。
6. 数据库负责算术、lag、求和、均值、样本标准差；Python 负责解析、调度和独立对照，不先算完整结果再写库冒充库内计算。
7. 每节点携带有效性和原因。完整窗口验证要检查预期日数及每个子值；SQL 的 AVG/SUM 默认忽略 NULL，不能直接当作规范要求的完整窗口结果。
8. 所有运算都以安全输入防护：除法 NULLIF/CASE、log 正域、sqrt 非负域、有限值检查。单只股票域错误不让整个批次中断。数值类型和容差需在测试中明示，不能只比较格式化后的字符串。
9. 暂停交易价格不用于价格因子；可靠零成交保留量额 0。输入缺失、历史不足、停牌、零成交及除权原因按规范传播，多原因保留明细。
10. 只在原始价格/股数跨日期比较的子树检查除权，不能简单让整个量价公式“只要出现 raw 就全部禁用”。
11. 同一计算保持稳定输入，优先使用 REPEATABLE READ 的一致快照，并固定研究日与财报快照；存储输入依据摘要及引擎版本。摘要只覆盖本次相关输入，不能让未来行情追加改变过去结果的依据。
12. 完成时在同一业务事务内保存 run、全部 value 和完成标记；错误整体撤销，通过独立请求日志记录失败。只允许有限结果或有解释的空值。

### 独立核对

- 每个因子用可手算小样本验证数值和原因，再对现有 20 只真实股票独立重算。
- MOM20、VOL20 与 B 对照；MA20_BIAS 的均价输入与 B 对照。若停牌处理与 B 原指标不同，只在双方有效日比较并单独解释差异，禁止篡改 B 计算来凑一致。
- 验证末端窗口、周末、上市初期、缺中间交易日、零成交、除权、非法有限数和历史不足。
- 修改研究日之后的行情，过去结果及相关输入摘要不变；改变实际使用过的过去输入，新运行依据必须变化，旧记录仍保留。

### 退出条件

10 因子全量核对通过；主要运算执行计划证明在库内完成；一个无效股票不影响同批其他股票；新增 D SQL 检查以及 ABC 原检查通过。

2. 工具从已认证服务会话获得用户和研究日期；客户端提交别人的会话编号、公式编号或运行编号，应统一拒绝。
3. AI 路径只读业务资料，计算和结果保存由可信受限服务完成；AI 角色不直接拥有写表或下单权限。
4. 请求开始、成功、失败、被拒绝、待核对等事件可关联；完成事件约束防止双重成功。请求重复提交必须定义为幂等重试或明确拒绝，不能重复模拟下单。
5. 公式发布、运行提交及关键交易业务事件与业务事务一致。可用受控函数或附加触发器，不删除 C 现有触发器，不改变成交记录只追加规则。
6. 请求记录在独立连接中提交，不在 read-only 业务事务内尝试插日志。普通应用和 AI 均不能修改或删除记录，审计查看身份也不能写。
7. 审计页遵守本人/授权审计范围；记录不包含密码、会话明文或完整敏感连接异常。
8. 工具调度层必须可脱离外部模型验证。若接入自然语言模型，提供可配置适配器，不硬编码供应商、模型或凭据。

### 退出条件

真实角色下越权、恶意公式、超时、业务回滚、记录写入失败和重复请求测试通过。任何模型建议均不能绕过工具限制直接执行数据库命令或交易。

没有外部模型配置时，完成工具层与适配接口、明确标记真实模型联调待配置；假响应只作测试，不能将固定菜单包装成已完成的真实 AI 问答。

## Phase 7：统一页面与 ABC 完整操作链

### 建议文件

`app/ui/main.py`、登录页面、`d_factors.py`、`d_audit.py`；必要时给现有 A/C 页增加正式身份适配；`tests/d/test_ui.py`。

### 页面内容

1. 登录与退出，研究日期固定显示，切换用户清理上一个用户的选择、私有结果和缓存。
2. 公共目录：中文名、定义、来源、日线改编说明、单位和历史长度，可查看或复制。
3. 私有公式：新增、校验、中文错误位置、版本列表、编辑新版本、归档。
4. 计算与筛选：日期、股票池、版本、阈值和排序分开设置；显示值、缺失原因、依据与私有运行记录。
5. 接入 A 历史页、C 交易页与三个原策略页，保留已修复的账户选择行为。
6. 选股结果进入模拟交易时只预填股票，由登录用户明确提交模拟订单，继续走 C 检查，不自动批量下单。
7. 操作记录按请求查询，能看到失败和被拒绝；用户不能通过切换编号获取他人记录。

第一版不增加自定义因子回测引擎。若决定新增，必须另列 C 扩展任务并保存公式版本及输入，不将选股页面等同于已完成自定义策略回测。

### 验收与退出

自动页面检查之后实际打开浏览器，走两个用户的完整流程；检查渲染、曲线、错误提示和操作归属。保存脱敏截图。正式入口无手填用户编号、无数据库密码输入框；独立旧演示如保留必须明确标记并与正式导航隔离。

## 三、实现检查中的固定原则

1. 核心逻辑有测试才算完成，但不为单纯文案、样式或显然可逆的小修改堆测试。
2. 不修改原公式凑结果，不使用未来数据、零填缺失或删股票掩盖错误。
3. 稳定对象标识作为页面选择值，新增账户/公式/结果不应悄悄跳到其他对象。
4. 凭据永不进入日志、截图或提交；实际服务仅监听本机，除非用户另行要求部署。
5. 不把原有 `.audit` 设计检查原型当作生产解析器，也不把已有 ABC 通过记录当作 D 验收。
6. 新增代码与文档的状态必须一致，若未配置真实模型，将该外部条件单列，不影响已完成数据库范围的准确交付。
